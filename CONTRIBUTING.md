# Contributing

Thank you for your interest in improving this Discord.js project! Contributions, bug reports, feature suggestions, and documentation improvements are welcome.

By participating, you agree to follow the guidelines below.

## 1. Before Contributing

- Check existing issues and pull requests to avoid duplicate work.
- For significant changes, open an issue first to discuss the proposed implementation.
- Keep contributions focused on the project's goals and existing coding conventions.

## 2. Reporting Bugs

When reporting a bug, please include:

- A clear description of the issue.
- Steps to reproduce the problem.
- Expected and actual behavior.
- Relevant error messages or logs, with tokens, passwords, and other secrets removed.
- Your Node.js and Discord.js versions, when relevant.

## 3. Suggesting Features

Feature requests should explain:

- What the feature does.
- Why it would benefit the project.
- How it could work.
- Any relevant examples or implementation ideas.

## 4. Submitting Changes

1. Fork the repository or create a branch if you have write access.
2. Make your changes in a dedicated branch.
3. Follow the existing project structure and coding style.
4. Test your changes before submitting them.
5. Ensure no credentials, bot tokens, API keys, or private configuration files are included.
6. Submit a pull request describing your changes and linking any related issues.

## 5. Code Quality

- Use clear, maintainable JavaScript.
- Follow the project's existing formatting and naming conventions.
- Avoid unnecessary dependencies.
- Handle errors appropriately.
- Do not introduce unrelated changes.
- Update documentation when behavior or configuration changes.
- Do not commit `node_modules`, environment files, or generated files unless explicitly required.

## 6. Security

Do not publicly disclose vulnerabilities involving bot tokens, authentication, permissions, or other sensitive functionality.

Report security issues privately to the repository owner whenever possible. Never include real credentials or sensitive user data in issues, commits, or pull requests.

## 7. Pull Request Review

All pull requests are subject to review.

The repository maintainer may request changes, accept or reject a contribution, or close a pull request at their discretion.

Submitting a pull request does not guarantee that it will be merged.

Be respectful, constructive, and professional when interacting with maintainers and other contributors. Harassment, abuse, spam, and deliberately disruptive behavior are not acceptable.
